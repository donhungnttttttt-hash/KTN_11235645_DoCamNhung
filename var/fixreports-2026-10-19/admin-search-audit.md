## FR-06 source findings

1. **Picker is not globally unassigned.** `AdminProjectForm.jsx:9-25` exports MemberPicker, calls `api.users({keyword,role?,enabled:true,page,size:20})`, then disables only `existingUserIds` of the current project. `AdminProjectDetail.jsx` uses that picker for additions. `AdminProjectService.java:61-74` has no unassigned predicate; `projectId` means EXISTS active membership in that selected project. It uses the same current WHERE for rows/count, which should be preserved. Client filtering an already paginated page would produce incorrect counts and miss eligible users.

2. **General AdminUsers must still list assigned accounts.** It uses the same GET `/api/v1/admin/users` endpoint with membership/role/enabled filters. Change the picker through an explicit `unassignedOnly=true` parameter, default false, rather than changing users() globally. Desired predicate: `NOT EXISTS (SELECT 1 FROM project_memberships m WHERE m.user_id=u.id AND m.active=TRUE)`. Apply it before both count and LIMIT/OFFSET. Historical inactive membership alone does not exclude a user. Active membership in an archived project still counts: C09 says any active membership, without a project-status exception.

3. **C09 is explicitly a picker rule.** Do not add `UNIQUE(user_id)` or globally forbid multiple memberships; do not deactivate existing membership rows. `ProjectService.addOrUpdateMember:86-113` already owns account/project locks, versioned restoration/change and DEV-role compatibility. Preserve current member table and role editing. Candidate lookup used by `AdminProjectDetail.saveSelected` retains inactive membership version handling. If a previously selected candidate becomes assigned while the picker is open, refresh and surface stale selection; do not silently transfer memberships. Any stronger write-time exclusivity rule would need to be distinguished from C09's approved filter-only change.

4. **Initial handover currently permits any selected member and different recipients per machine.** `InitialDevicePicker.jsx:6-18,29` considers every passed member valid, offers common recipient plus per-asset recipient editors. `AdminProjectForm.jsx:30-37` stores/sends recipient per device. `DeviceInventoryService.allocateInitial:69-76` checks selectedUsers and duplicate assets, but allows multiple recipient IDs. `assignLocked:58-66` verifies active project membership only, without PM role. UI-only restrictions can be bypassed through API.

5. **All handover entry points need the same PM rule.** `DeviceAllocationDialog.jsx:12-18` permits active/enabled/known members. `ProjectDeviceAssignDialog.jsx:12-22` permits all active/enabled members and posts devices individually; `InitialDevicePicker` is reused there. Keep admin-managed handover/return, machine identities, recipient identity, dates, notes, optimistic versions, availability and lock order. Enforce active PM membership + enabled account inside the locked assignment path. Initial selection batch must have one distinct recipient and all selected devices inherit it; preserve optional per-device notes/return dates. There is no justification for adding a PM-to-member allocation workflow.

6. **PM role needs a consistent existing interpretation.** The current project model uses projectRole for PM authority. `ProjectRoleSelect.jsx:5` allows any non-DEV system account to be PM/TESTER; `ProjectService:94-97` only enforces DEV compatibility. Consequently checking only system `role_code='PM'` would reject existing legitimate project PMs and differ from project authorization. Recommended contract: `membership.projectRole==='PM'`, active, account enabled. If root chooses system PM instead, record that extra rule explicitly in the shared contract; do not let UI/backend choose differently.

7. **Existing member-level device presentation should become PM handover language.** `ProjectDevices.jsx:11` says handed to member; `AdminDevices.jsx` AllocationTable displays recipient (keep it as PM recipient), while project preparation points to giving the executor a machine. Do not erase historical recipient information to make old non-PM allocations look like PM handovers. Restrict new writes and remove member-distribution UI/dependencies; preservation/remapping of old non-PM allocations must follow the root migration decision.

8. **Duplicate role chart is localized.** `AdminDashboard.jsx:30` contains both Total/Active role table and `MetricBars label="Phân bố vai trò hệ thống"` over the same byRole totals. Remove that MetricBars instance; keep Total/Active table, Membership-by-project chart and inventory chart. No new backend query or migration is required for this removal.

9. **Sidebar currently scrolls with the document.** `admin.css:1-12` uses grid shell with auto header + 1fr content, aside flex, and mobile wrapped navigation; no sticky/fixed positioning or bounded sidebar overflow. Small bounded fix: sticky sidebar aligned to start with viewport-bounded height and its own overflow-y, plus mobile treatment that keeps all menu entries accessible. Avoid a fixed width/height desktop rule that blocks the main content or traps small-screen navigation. Verify at 320/375/768/1440px, long page, short viewport and keyboard navigation. Existing `AdminLayout` skip link and chat launcher must remain usable. This file is already dirty; merge changes with the current content.

## Proposed bounded interfaces and query rules

These are proposals for root's shared contract, not edits performed here:

* Keep endpoint-specific `keyword`, paging/filter/project parameters and response types. Tokenization module has a small interface `tokens(keyword)`; local matcher has `matchesTokens(fields, tokens)` with every token required somewhere in the approved fields. Normalize Unicode decomposition, combining marks, lower-case and explicit đ/Đ to d, trim and split repeated whitespace; empty query matches all otherwise permitted rows. This keeps implementation complexity out of every caller.
* Backend SQL adapter accepts tokens plus source-owned trusted text expressions, produces bound predicate and arguments. Shape: AND across tokens, OR across that list's allowed fields for each token. Reuse the exact predicate/arguments for count and data, then apply stable existing ORDER BY/LIMIT/OFFSET. No user-controlled SQL field/expression interpolation. LOCATE with bound literal tokens avoids wildcard interpretation of percent/underscore; an adapter using LIKE must escape its escape char plus percent/underscore.
* SQL must fold stored values as well as input. Lowercasing/folding tokens alone cannot match an accented stored column. Use explicit utf8mb4 conversion for ASCII columns and an explicitly tested accent/case-insensitive collation or normalized searchable projection. Explicitly normalize đ/Đ; do not assume database default or collation behavior without the native test. Root owns selection of reusable adapter and any migration; no schema change is required merely to add NOT EXISTS or audit joins. Test composed/decomposed Unicode and native MySQL semantics separately from mocked SQL unit assertions.
* Keep existing max keyword/page-size guards (Admin 100, work item 200, document 255), or deliberately align them in shared contract. Do not silently drop excess tokens or use a result cap as global total. Query projection must be scoped before matching.
* Keep useAdminRead's AbortController + `live` guard/key masking (`shared.jsx:4-22`) and existing keyword-reset-page behavior; it already prevents stale results being committed. Preserve AdminUserProjectFilter's debounce and pendingSearch disabling; extend tests, not a second fetching abstraction.
* `GET /admin/users?...&unassignedOnly=true` is additive; false/default keeps existing general administration behavior. Both query and count include its NOT EXISTS predicate. MemberPicker preserves selected users across pages and must not turn hidden page selections into deselections.
* Initial handover can retain current `devices[]` contract with one `recipientUserId` shared by every item and a server distinct-recipient check. UI holds one common PM and emits the identical recipient per device. This avoids changing every inventory DTO while enforcing the approved batch invariant. Ordinary single-device Admin assignment remains supported with the same PM validation.

## Audit-specific interface and time behavior

Recommended final call shape: `audit({projectId?,keyword,from?,through?,page,size})`; remove type/timezone from active UI and contract. Use a server constant `ZoneId.of("Asia/Ho_Chi_Minh")` and the same constant for `toLocaleString` in the client. Current controller default is **UTC**, although UI supplies Vietnam; direct API requests currently differ.

Keep existing safe EVENTS UNION projection; never search raw audit metadata, credentials, request/session IDs or payloads. Search allowlisted actor display name/username/ID, project name/code/ID, object type/ID and action. Existing object display is translated type + ID, not an arbitrary entity payload. If keyword should find the Vietnamese labels users see (for example “bàn giao”, “tài khoản”), include a fixed public label mapping in the backend search projection or return canonical labels from one owned vocabulary; do not have client-only labels with server-only English codes accidentally produce different behavior. This is a display/search consistency choice within C12, not permission to inspect confidential metadata.

Count must include the same LEFT JOIN identity_users/projects or a shared derived projection as the row query; current count has no joins because it previously filtered only e.*. Preserve no-project system events in all-project scope and exact project predicate when project selected. Preserve ADMIN-only authorization and sanitized output fields.

Date window: `occurredAt >= from.atStartOfDay(VN)` converted to UTC, and `occurredAt < through.plusDays(1).atStartOfDay(VN)` converted to UTC. Current service already has this half-open pattern, but allows arbitrary timezone. For through=2026-10-19, upper UTC bound is 2026-10-19T17:00:00; include 16:59:59.999999, exclude 17:00:00. On that local date lower UTC bound is 2026-10-18T17:00:00. Do not use 23:59:59 truncation. Validate malformed dates, reversed dates and supported range before plusDays(1); do not convert overflow to HTTP 500. Existing controller LocalDate parse and service reversed-range check must remain covered.
