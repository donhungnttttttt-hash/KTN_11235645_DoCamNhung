## Confirmed defects repaired

1. **P1, accidental coverage write on pagination.** Repro: in the coverage editor, select a case, enter a reason, then click **Tiếp**. The shared Pager buttons in `test-execution/components.jsx:10-13` were implicitly submit buttons inside `retest/CoverageEditor.jsx:14-24`; one click both changed the candidate page and called the coverage save handler. The RED test `retest/retest.test.jsx:93` observed `onSubmit` called. Both page buttons now have `type="button"`; the test is GREEN. This preserves the explicit confirmation step and prevents an unintended coverage revision.
2. **P2, long-form save error not brought into view.** In `retest/RetestPanel.jsx` and `RetestResult.jsx:32`, `RetestError` appeared above the forms after a failed write. A user near the save button could remain at the bottom with no visible explanation. `retest/shared.jsx:21-24` now gives the alert a programmatic focus target and focuses it when an error appears. RED tests for failed coverage/result writes checked focus and draft retention; both are GREEN (`retest.test.jsx:29,64`).
3. **Reusable retry control could submit a containing form.** No current `test-execution` call site places `ErrorNotice` inside a form, but `components.jsx:15` exposed an implicit submit button. A RED regression mounted it inside a form and observed an unwanted submit. The retry now has `type="button"`, and `retest.test.jsx:12` is GREEN. This is a guard against the same defect when the component is reused.
