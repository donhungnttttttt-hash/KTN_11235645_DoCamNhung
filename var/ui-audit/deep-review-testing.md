## Confirmed defects and bounded repairs

1. **P1: grouped run reassignment bypassed file-group safety.** `ExecutionRunnerPage.jsx:68` opened the generic assignment dialog for a grouped run; `ExecutionService.assign:152-159` changed one canonical assignee while `FileWorkService.assign:311-329` required all-run reassignment and rejected active sessions. Reproduced on isolated V29 schema: generic assignment succeeded during a DOING session. The runner now offers **Giao lại file** and navigates to the group. The generic backend endpoint returns 409 `FILE_GROUP_ASSIGNMENT_REQUIRED` for grouped runs, including direct API callers. New test asserts the active session and run assignee stay intact. The normal ungrouped assignment route remains available.
2. **P2: retest authority became stale after a failed read.** `RetestPanel.jsx:14-34` and `RetestResult.jsx:12-44` retained previous server data after a refresh error; mutation controls remained enabled. Both now mark authority uncertain on a failed current read, keep the entered draft, show why saving is blocked, and unlock after a successful refresh. Result detail has an explicit **Tải lại yêu cầu** action. The write guards still enforce server permissions.
3. **P2: scope setup offered a misleading retry after a failed write.** `ScopeSetup.jsx:13-36` used the same error for case-list reads and configuration/scope writes. The displayed **Thử lại** only reloaded the manual case list; in the default file mode it did nothing after configuration save failed. Read and write errors are now separate. The list has a retry action only in manual mode; write failures keep the draft and use the original labeled save action. Switching back to file mode hides a stale manual-list error. Three RED regressions now pass.
4. **P2: successful revision save could leave stale case detail without recovery.** In `CaseDetailModal.jsx:46-103,131-135`, a revision or approval POST could succeed and the subsequent GET fail. The dialog retained old case data but hid its read retry because `caseData` was still present. A failed read now has its own retry even with retained data; mutation actions stay disabled until refresh succeeds. Write failures remain separate, preserve the draft, and have no misleading read retry. A RED revision-save/refresh test is GREEN and verifies retry does not repeat the POST.
