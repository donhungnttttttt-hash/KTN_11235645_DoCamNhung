============================================================
# 4. PHÂN BIỆT ARCHITECTURE VÀ IMPLEMENTATION
============================================================

Đây là nguyên tắc cực kỳ quan trọng:

ARCHITECTURE CORRECTNESS != IMPLEMENTATION COMPLETENESS

Nếu code hiện tại còn thiếu rất nhiều chức năng, KHÔNG được mặc định architecture sai.

Ví dụ:

Nếu hệ thống hiện tại mới có:

UserController
UserService
UserRepository

nhưng chưa có Order, Payment, Notification...

thì chưa được kết luận rằng architecture sai.

Có thể chỉ đơn giản là các feature chưa được implement.

Ngược lại, nếu:

- Controller chứa business logic
- Frontend tự quyết định business state
- Repository chứa business rule
- Service truy cập database trực tiếp bằng SQL rải rác
- Domain logic bị duplicate
- API trả trực tiếp database entity
- Module phụ thuộc vòng
- Authentication/authorization không có boundary rõ

thì phải đánh dấu là architectural problem.
