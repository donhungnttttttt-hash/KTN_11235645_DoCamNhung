# Role-based AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Triển khai native trong phiên làm việc hiện tại, theo quyền thực hiện người dùng đã cấp; không đổi nhánh. Một reviewer cuối lượt độc lập theo executing-plans; các task implementation thực hiện tại chỗ.

**Goal:** Trợ lý AI theo quyền cho bốn vai trò, kết quả lưu tạm và thao tác an toàn.

**Architecture:** Backend dựng context từ SQL có scope, gọi Responses API ngoài transaction rồi lưu bản nháp MySQL. React dùng một màn chung và API theo tác vụ; output là gợi ý do người dùng xem/chỉnh/sao chép, không cập nhật nghiệp vụ tự động.

**Tech Stack:** React JavaScript, Spring Boot 3.5/Java 21, MySQL native 3307, Flyway, Java HTTP client; không dependency mới.

**Spec:** `docs/superpowers/specs/2026-10-09-role-ai-design.md`

## Global Constraints

- Nhánh `system-design`; giữ bí mật trong `.env.mysql.local`, không stage `var/`.
- Test có ghi dữ liệu chỉ chạy schema `tms_docstest_<12 hex>` đã xác minh; không reset `tms`.
- Mặc định TTL 7 ngày (1–30), quota 20/project/ngày UTC (1–100), timeout 20 giây (1–30); request 16 KB/response 64 KB.
- Không tự ghi kết quả test, gán người, đóng bug hoặc gửi thông báo; không gửi dữ liệu dự án thật trong test live.
- API và UI trả trạng thái thực; không dùng mock fallback khi provider lỗi.

## Review Focus

- Thu hồi membership/khóa account trong lúc AI đang trả lời: reauthorize trước save/read.
- Refresh/timeout/double-click: request key ổn định, một reservation, trả draft cũ.
- Sai project/role khi đọc cache: owner + permission hiện hành, không chỉ dựa vào ID.
- Prompt injection và citation bịa: server prompt/schema, whitelist nguồn và output bounds.
- TTL/quota và đổi ngày UTC: hết hạn không đọc được, cleanup bounded, quota không reset theo process.
